## 连不上、失控与网页故障的分层判断

这次不是一个可用“重启网络”概括的单一问题。最近三天原始覆盖窗口、缺失和版本分桶以[三天复核](2026-10-17-three-day-review-and-solution.md)及其脱敏 evidence 为准；本补充只扩展到 10 月18日的新窗口，不声称连续监测了完整72小时。

- **已从实际代码和反例确认：** 初始画面超过8秒时，旧 Viewer 会转入终态，而稍后到达的新鲜画面不能重新打开真实 Input gate。新方案保留8秒慢连接提示，使用同一 Start 所有权内有限的主动等待预算；不放松已终止连接的输入门禁。最初复审又找出旧 reclaim 失败误终止新 Start、自动 refresh 恢复阻挡连接层两处边界，已补反例与修订；Task1逐项复审通过后，最终跨层review又发现初始PC保留而socket替换时回调仍持有旧归属；380b250已补实际恢复反例并修订，定向最终复审通过，尚未上线。
- **已确认的日志缺口：** 没有 Host 时 v2输入/offer 被误称为旧 Host 协议；控制 reset 的 fail-closed 入口日志被误读为执行失败，成功回到 FREE 缺少正向事件。Task2应仅修分类和补确切完成事件，保留真实授权、复位 ACK、重试与不重放策略。
- **已确认的同步 I/O 风险：** Host 的旋转文件写入/flush/轮转在调用日志的线程执行，可拖住事件循环。Task3用单个有界 writer 隔离文件I/O；队列满/单行超限/写入错误明确计数，有限关闭允许报告 writer 尚未退出。尚无同窗线程栈证明它就是全部历史停顿的根因。
- **仍缺归因：** 无媒体时也有7.642/15.647秒 loop迟到，说明不能仅怪视频编码。资源收集的 subprocess spawn 在首个 await 前、系统调度和换页仍是候选边界；在本轮三项改动实测后，再决定是否按独立 spec 实施完整 spawn/cleanup 隔离。只把 communicate 放线程不能证明隔离。
