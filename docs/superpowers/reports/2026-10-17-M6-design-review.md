# M6 independent preimplementation design review

**Verdict: IMPORTANT BLOCKERS — make the two corrections below before implementation.** The bounded TTL/exact-ACK/origin approach is coherent; no new controller or policy redesign is required.

1. **P1 — The strict initial-start handshake is unspecified and incompatible with the actual generation-0 path.** Spec §4 requires all scope numbers positive, records expected scope only from an accepted media-control ACK, and describes binding only in `_apply_tunnel_media_control`. Actual `webrtc.js::startTunnelRelay` calls ordinary `emitRelayStreamControl` without `mediaControl`; `replayMediaActivityIntent` rejects generation 0. Host ordinary `on_relay_stream_control` starts the producer without sending a control ACK; `on_connection_attempt_bind` establishes media binding generation 0. Thus applying the described strict filter leaves a fresh connection rejecting every frame, even though pause/resume tests with generations 1/2 pass. Minimal correction: explicitly design initial start. Either retain authenticated generation 0 with a distinct current-start ACK acceptance rule (and nonnegative mediaGeneration only), or deliberately create the first positive media intent through the existing controller/runtime before ordinary strict start. Document Host/Signal/Viewer sequencing and reject legacy fallback as strict proof. Add an end-to-end offline real-handler test from fresh controller/runtime generation 0 through bind/start/ACK/first onload, plus fallback into tunnel and producer restart on the same attempt.

2. **P2 — The prescribed RTT sample key collides across relay scope changes.** M6.3 gives `sampleKey: String(sample.sampleSequence)` while feedback/sample sequences are per relay scope. `WebRTC.latencyScope()` uses connectionAttemptSequence, not media generation or producer identity; it remains unchanged across suspend/resume and same-attempt producer replacement. `latency-monitor.js::push` deduplicates keys among retained samples. A new producer's sample 1 therefore collides with the prior scope's sample 1 within the five-second window, silently discarding valid RTT (and potentially leaving a prior producer value displayed). Minimal correction: use a bounded composite key containing the full relay origin and sampleSequence; explicitly define whether the shared collector retains earlier valid samples within its existing five-second scope window. Do not reset the entire collector and discard unrelated input measurements merely to fix this. Add a real collector test accepting two sampleSequence=1 samples from different accepted relay scopes under unchanged collector scope, while rejecting same-origin duplicates and late foreign feedback.

## Required precision when updating the documents

- RTT is selected twice: only matched ACKs strictly below the 2000 ms slot TTL are eligible, then only the latest eligible sample per feedback interval survives coalescing. Spec already says coalesced/non-full distribution, but must explicitly state the TTL censoring so reported p50/p95 cannot imply overall path latency or absence of multi-second stalls. Preserve expired/unmatched/coalesced counts alongside the sample population; define counter reset scope and expose coalescedCount in the wire whitelist (it is mentioned narratively but omitted from the enumerated feedback fields). Arrival-based five-second collector freshness means time since feedback receipt, not proof of current frame freshness.
- Do not make the UI five-second stale transition solely a diagnostic state update: current `canEnableDesktopInput` does not inspect uiPhase; `syncDesktopInputGate` does. Keep the proposed explicit `setActive(false, {resetKeyboard:true})` before the normal gate sync, and assert the effective business gate, not just `Input.isActive`. The actual controller snapshot does use `RESET_REQUIRED` and `pressedKeyCount`, so the provided inactive-keyboard fallback matches source. Fresh-frame `setActive(true)` may run existing `_maybeAutoRecover`; tests must match the reset IDs currently owned by C3 rather than assuming the first reset ID always completes recovery. Include already-inactive and failed/timeout reset cases; do not clear barriers to satisfy the test.

## Checks that passed at design level

- Exact per-frame pop independent of the progress watermark, monotonic 2000 ms expiry before admission/after wait timeout, wake on release, and no new expiry-driven downshift address the demonstrated liveness defect. Preserve actual-loop bounded-yield and worker-limit tests.
- Producer nonce plus authority attempt/lease epoch/media generation and production generation closes restart/frame-ID reuse; validating before watermark and again inside token-guarded onload covers both queued old arrivals and replaced callbacks. Dropping frames until ACK is acceptable only once the initial handshake above is complete; TTL supplies subsequent frames.

## R1 scoped re-review — 2026-10-17

**Verdict: PASS at design level; implementable. Both original blockers are ADDRESSED. No new design blocker found in the revisions.** This verdict does not assert implementation or runtime acceptance.

- **P1 / initial generation-0 start — ADDRESSED.** Spec §4 now permits mediaGeneration=0 while keeping productionGeneration/leaseEpoch positive. Ordinary start carries a fresh bounded request nonce, actual attempt and requested media generation without accidentally entering the positive-generation media-control branch. Signal validates/forwards on the actual ordinary route; Host validates active authority/media binding under the existing media lock, binds the producer before work, rechecks after awaits, and emits a request-correlated start ACK. Viewer dispatches this ACK before the explicit-control runtime branch, consumes only the exact pending socket/lease/attempt/generation/request nonce, and does not mark media ready on ACK. Existing positive-generation pause/resume retains its runtime path. M6.2 now requires fresh generation-0 real handlers and first onload, fallback, restart, duplicate and stale ACK tests. This resolves both the invalid positive-only schema and missing first-start ACK path.

- **P2 / RTT key collision — ADDRESSED.** Spec §6 and M6.3 define SHA-256 of the canonical full origin array plus sampleSequence: `relay:<64 hex chars>:<up to 16 decimal chars>` is at most 87 printable ASCII characters, below the actual collector's 128-character limit. SHA-256 is computed once per accepted origin, not per frame; completion must recheck current socket/origin token. Missing Web Crypto leaves only this optional metric unavailable. Different relay origins sharing one collector scope can retain sample1 independently; actual collector tests cover this, duplicate/foreign rejection, long identifiers, late digest completion, retained input metrics, and UI cache clearing.

- **RTT population precision — ADDRESSED.** Documents explicitly limit eligible RTT to <2000 ms before latest-per-interval coalescing; coalescedCount is now in the white list with reset/saturation semantics. p50/p95 cannot claim overall latency or absence of stalls. Feedback receipt age remains distinct from image-load freshness. Valid earlier-origin collector rows expire naturally; current-origin UI cannot reuse their last value.

- **Input reset identity / test precision — ADDRESSED.** M6.3 now checks effective business dispatch and actual current C3 reset IDs after `_maybeAutoRecover`, including rejected/timeout and already-inactive cases. No new reset controller or direct barrier clearing is introduced.

### Implementation checkpoints within the accepted design

1. On every pending strict start, including same-attempt restart/fallback from a previously ready path, explicitly invalidate the old ready proof and synchronize the actual Input gate. Actual `startTunnelRelay` currently calls `setUiPhase('signaling')`, but `setUiPhase` does not call `syncDesktopInputGate`; UI state alone does not close Input. Exercise the revised first-scope-onload requirement from a fixture that was already ready/active: before ACK and after ACK but before the accepted new onload, business dispatch must remain blocked. This implements the stated contract, without adding a controller.
2. Precompute the digest at origin acceptance; do not make frame readiness depend on diagnostic hashing. A feedback received while the digest is unavailable may leave the metric unavailable until a later feedback; do not create an unbounded async buffer or substitute an unsafe key. If a sample is deferred, preserve receipt time and account for the actual collector's monotonic-clock rejection of timestamps older than intervening collector calls; do not manufacture a newer sample time. Recheck the origin token before any async completion can update UI/collector state.
