## Finding and recommendation

The production ordinary recovery implementation already exists, but there is **no existing automated initial admission path that both atomically preserves zero-Viewer/human priority and enters ordinary resumable ownership**. The proof path deliberately cannot recover. A `/api/status` zero-Viewer check followed by ordinary UI Start is unsafe: ordinary Start's ticket is permitted to supersede whoever connects between check and handshake. Repeated strict proof runs cannot close the ordinary-recovery acceptance gap.

Recommend a separately specified and independently reviewed **guarded ordinary initial ticket** policy. Its only authority difference from ordinary Start is narrower initial admission: reject if occupied, any intervening Viewer admission, or conflicting human Start intent. Once admitted, it must use the existing ordinary `connected.viewerAdmission` and current-owner resume code unchanged, including Host barriers. Keep the existing proof protocol and strict continuity runner unchanged. This is a real admission protocol/authority extension, not a helper-only refactor, proof reuse, or an existing permission hidden behind a test flag. Parent must first amend the current Host-only spec/plan and record review. This assessment does not implement or authorize the extension.

Under the root's supplied user authorization for full implementation/maintenance/acceptance, preparing and reviewing this bounded extension is within the overall objective without asking repeated workflow questions. That authorization does not erase the active Host-only constraints: no deployment or new production test capability under the old spec. Root should explicitly record the new scope and its unchanged prohibitions before implementation. Native business input, grace/deadline/quality changes, tunnel changes and proof weakening remain outside this proposal.

## Options compared

1. **Existing ordinary UI Start plus status polling:** no source change, real ordinary resume, but races and can evict a human. Reject for production automation. Waiting until no visible human or choosing an obscure session does not make admission atomic.
2. **Observe an already established human ordinary session read-only:** valid evidence if such a session is already available and observing it is authorized, without reconnect clicks, native input or synthetic ownership. Cannot guarantee timely interruption/recovery or reproducible matrix, and none is established in the supplied current state. Do not claim qualification from absence of a disconnect. This is the sole existing production path worth using opportunistically.
3. **Guarded ordinary initial ticket (recommended):** smallest safe production path with representative automatic ordinary resume. New initial policy is explicit; post-admission logic remains ordinary. Requires coordinated server, small Viewer admission adapter, separate runner/tests, and docs; strict proof remains intact.
4. **New dedicated resumable test capability/protocol:** can bind a test identity, expiry and human-first revocation, but requires its own resume validation and lifetime semantics; risks testing that new protocol instead of ordinary current-owner recovery. Larger security/authority surface than narrowing the existing ordinary ticket. Only choose if independent review proves a narrow ordinary admission extension cannot preserve guard semantics.
5. **Isolated server/fake Host/loopback laboratory:** useful for exhaustive deterministic RED/GREEN and races, but cannot qualify actual production Host/public-network recovery. Existing proof-only Lab forbids ordinary issuance (`routes/auth.js:101`) and must not be weakened to make evidence appear production-equivalent.
6. **Convert an accepted proof to ordinary, clear its marker, remint on disconnect or replay proof:** prohibited. Changes proof semantics or bypasses the protection and cannot yield trustworthy ordinary acceptance.

## Required initial-ticket semantics

This is design guidance for a separately approved spec, not an executable patch.

- New optional server-validated **narrow initial policy** stored in the ticket record; an absent/ordinary policy keeps current human behavior. Never trust only a client boolean at handshake. Bind role/auth subject/session and retain existing TTL/capacity. Reject malformed or unsupported guard requests without ordinary fallback. Proof-bearing pages cannot use this policy, including corrupt proof markers.
- At issuance, require zero desktop Viewers (including disconnected grace records) and the established acceptance preflight Host-online/relay-zero conditions. At first consumption, synchronously verify occupancy and the server admission epoch captured at issuance before mutating owner, sequence, proof state, map or lease. A human who connects and leaves between issuance and consume must still invalidate the ticket. Do not use only current Viewer count.
- Preserve pending **human Start intent** as well as admitted-human priority. Current ordinary issuance increments `sequence` even before admission. Naively calling `issue()` for an automated guarded ticket would invalidate a previously issued human ticket and let automation win. Guarded issuance must not advance/invalidate ordinary human ordering. Reject or defer when an unexpired unconsumed ordinary human ticket exists; a later human Start must invalidate a pending guarded ticket. Cover human intent before issuance, between issuance and consumption, and accepted-then-disconnected. Use bounded existing map/high-water evidence; never evict consumed evidence to fit another ticket.
- On successful guarded initial consumption, enter ordinary owner bookkeeping and return the exact existing resume generation; normal automatic retries thereafter carry that generation. Existing proof admission remains separate and cannot be exchanged. The ticket may need existing lost-welcome current-owner retry semantics; call that an ordinary ticket retry, never claim a strict single-use proof is being reused. Once a different human owner is admitted, all test resumes and consumed-ticket retries must reject without map/lease/proof effects, even if human later disconnects or TTL expires.
- Existing accepted-ordinary bookkeeping (`noteHumanViewerAdmission`) invalidates proof reservations. That effect must be explicitly reviewed/documented for a guarded ordinary owner; no promise that a pending proof survives successful ordinary admission. Rejected guarded admissions must preserve proof and human state. Parallel proof/guard issuance and consumption require race tests.
- Use fresh disposable authenticated page, actual one UI Start action and narrow policy selection through reviewed production code. Do not monkeypatch `requestExplicitViewerAdmission`, Socket.IO, grant handlers or control gates; do not inject a raw resume generation as if a welcome occurred. Keep proof page restrictions. On missing/malformed marker, auth change, timeout or denial, stop; never silently issue unrestricted ticket.
- Once test owner admitted, runner performs no further Start/reclaim/ticket issuance. Ordinary socket recovery is product code. Human arrival ends/marks test superseded; runner never clicks reconnect to regain ownership. Cleanup touches only the disposable browser/session; it must not disconnect a new human Viewer.
- No new lifetime/grace/rebind/heartbeat/control deadline, no synthetic Host ACK, no changed input gate. Admission itself does not grant input. Required existing control-acquire/reset lifecycle remains; business native input remains zero.

## Recovery qualification contract

Use a separate bounded ordinary-recovery result; do not relax or rename existing continuity PASS. Maintain first-close provenance and loss/observation gaps.

- Stable pre-interruption baseline: exact deployed source/build, same authenticated session and ordinary admission generation, Host online, actual selected TURN/STUN/tunnel path, active lease, fresh rendered frames, matching reset/media readiness evidence. Store salted equality hashes/enums/counters, never credentials, ticket/session raw values, input contents, coordinates or candidate addresses.
- **Within grace with live active Host lease:** resumed socket is the same current ordinary owner generation; socket ID may change. Same lease epoch is expected only when Host rebind actually succeeds. No control grant/input eligibility before matching applied Host ACK and Viewer recovery barriers. A server-side grace interval starts on server disconnect detection, not browser close; compare observations without inventing one-way timing.
- **After grace or failed/unavailable old lease:** same ordinary admission generation may still recover, but lease epoch changes via existing reset/regrant. Old PC/attempt may be retained only where existing code permits; when the new lease requires new peer/offer, observe actual new attempt/PC and fresh frames. Do not insist on identity continuity or count old continuing media alone as recovered control.
- **Human B supersedes A, including while A is offline:** B's ordinary admission supersedes; A's resumed handshake rejects, no later ticket/remint/manual reclaim, B's lease/media unchanged by A. Include same-session new-generation stale retries and B-disconnect-before-A-retry. Actual synthetic B production takeover is not automatically covered by the initial zero-Viewer rule: test races offline first; production B test would require a separately bounded human-equivalent takeover capability/explicit live procedure, or observation of an actual human arrival. Do not invent such permission here.
- **No replay:** runner sends no business input before/during/after outage; source/VM tests verify pending/uncertain input cannot be replayed across recovery and stale grants/ACKs cannot open input. Passive runtime eligibility/reset/fresh-frame evidence is not actual business-input or optical qualification; activeControl and visibleEffect remain NOT_RUN. Do not reinterpret mandatory safety resets as a tested desktop business action.
- Natural interruptions can be observed first, but are not reproducible on demand. For reproducible within/after-grace runs, separately specify a browser-session-local network fault adapter (e.g. bounded CDP connection impairment) with cleanup and identity confinement. It changes test conditions and must be reviewed; never stop Signal/Host/tunnel, globally disable networking, invoke native input, rewrite product Socket.IO timers or force `.connect()`/admission. Browser offline affects media too, so label it an induced outage, not a reproduction of WS1006 with continuing media. A targeted WS-only fault is more representative but requires separate tooling review, and should not be assumed available. Wait for server-observed lifecycle to classify grace outcomes. Delays chosen in tests are stimuli, not changed production deadlines.
- Server restart clears ordinary owner by design; unknown resume rejects and needs explicit new UI Start. Do not claim seamless server-restart resume is part of this qualification or add persistence within this task.
