## Minimal diagnostic improvements worth planning

1. **Persist a bounded established-session close summary in the Viewer.** Current production `recordSignalingFailure()` and `sanitizeSignalingFailure()` describe only `last-connect-error`; the current disconnect handler freezes control and schedules recovery but records no equivalent close summary. Add a separate fixed-schema record for first close per current signaling session, elapsed time, reason enum, transport/state, WebSocket close code/wasClean when available, last ping-received/pong-created/flush ages, visibility/online/focus booleans, and recovery outcome/deadline. Keep missing values null and maintain first-terminal separately from a small bounded tail. Apply the same whitelist at runtime/core/storage/server boundaries, retain no raw error or WebSocket reason string, and catch hostile getters. Diagnostic collection must not change recovery policy or business event ordering.
2. **Preserve server transport metadata where the installed library actually exposes it.** `viewer-heartbeat.js` currently observes Engine packet/flush/close and namespace disconnect, but ignores Engine close description/error metadata. Installed Engine.IO WebSocket forwards native ws close into `Transport.onClose()`, which emits `close` with no arguments; the Engine-level generic transport-close has already lost native close code. Merely adding an Engine close second argument cannot reconstruct it. If needed, a carefully scoped, diagnostic-only observer of the currently enrolled underlying ws emitter can project numeric code and fixed error class, removing listeners on finalization and guarding transport replacement/capacity. No raw native reason buffer, stack, address or private object should be retained. Avoid dependency patches or reordering business listeners. Code/cleanup and replacement tests would be required before adoption.
3. **Qualify recovery independently of hop attribution.** Current proof run ends immediately on the safety gate interruption and intentionally does not exercise ordinary resume authority. A safe, separately reviewed ordinary-session recovery qualification can establish whether a transient close recovers without manual refresh while preserving fail-closed input, human priority and existing deadlines. Do not remint or replay one-use proof or interpret this failed long run as resumed.

These are proposals only; no code, test, replay, live enrollment or restart was executed. The separately established reset/zero-viewer cleanup ACK race is post-failure and remains a distinct actionable issue. This hop audit does not reinterpret it as the initial WebSocket cause.
