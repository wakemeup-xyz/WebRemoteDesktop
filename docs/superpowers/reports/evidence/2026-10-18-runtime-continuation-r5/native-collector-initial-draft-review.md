# Native latency collector drafts — read-only review

**Result: changes requested in the draft contracts before implementation handoff.** This is a design/plan review, not source implementation or runtime approval.

## Findings

1. **[P2] Pass the live transport identities into the final evidence fence.** Design lines 42–43 require a *current* reliable ACK source and prohibit source changes from inheriting evidence, but `readControlledInputEvidence` at lines 71–72 receives only scope/lease/stream/PC. It cannot detect replacement of `inputChannel`, `inputMoveChannel`, or the Socket.IO object/ID while those other fields remain unchanged. In particular, a completed slot can survive such replacement until export; for unordered moves, comparing an incoming old-channel ACK only against the source saved at send also does not establish that it is still the current reliable channel. Existing C validation cannot supply that guarantee for moves: `acceptObservedInputAck` explicitly takes its unordered early-return path (`web-client/js/webrtc.js:1321–1331`), and the M1 unordered ledger checks transport/scope rather than channel ownership (`latency-monitor.js:159–172`). Specify an explicit live transport snapshot for ACK validation and final read, including the current selected send source, current reliable ACK source, and current socket object/ID as applicable. Keep these references private. Add a case where sources rotate **after all three observations but before read**, plus an unordered ACK from the previously reserved channel after the current reliable channel changes. Both must invalidate the slot without changing product ACK handling. This requires a contract amendment, not a new listener or authority mechanism.

2. **[P2] Name and carry the original send/ACK clocks through the fixed step result.** Design lines 127 and 154–155 require a fixed-key safe step containing raw Viewer event times sufficient to audit the deltas, but the enumerated in-memory step schema contains only durations and post-apply/visible FrameKeys. It has no send or ACK timestamp fields. `native_latency_artifact` receives only `step_results` (lines 116–118), so its fixed projection cannot recover those clocks without an undeclared field or copying raw evidence. Define explicit nullable scalar send/ACK clock fields in the in-memory and safe row schemas, or explicitly remove the audit-clock requirement. The former fits the stated goal and remains metadata-only. Update Task 3's positive fixture and privacy/schema tests so the actual accepted-send time and original ACK-entry time survive projection unchanged and reproduce all three Viewer deltas. Also spell out the exact names of the added ordinal labels/counters and the finite step reason enum; the current text calls these fixed schemas without enumerating those keys/values.

3. **[P2] Make post-apply waiting and terminal finalization callable.** Design line 92 distinguishes nondestructive intermediate PENDING reads from a final INCOMPLETE export, but the five browser APIs and three adapter methods provide no finalization argument/method. Task 4 step 3 retains ACK → claim → receipt → visual waits and immediately reads/evaluates the slot; it does not specify a wait for the independent M2 match. The existing M2 join can arrive after its original rVFC callback (`webrtc.js:261–277`, `:6276–6278`), and the draft correctly allows marker and M2 frames to differ. Consequently a valid marker can finish its wait while M2 metadata is still pending, yielding a premature failure, or an implementation must invent an unspecified terminal transition. Define one bounded native-mode completion poll using the existing page-read/poll mechanism and the slot's original 10-second deadline, then an explicit ID-bound finalizing read (or another concrete five-API-compatible terminal rule). Do not extend the slot lifetime or add a browser timer/listener. Cover timely late M2 joining, timeout with missing M2, and refusal/exception cleanup; the exported evidence must have a deterministic terminal reason rather than PENDING.

## Scope and positive assessment

The selected architecture is appropriate for the bounded increment: one LatencyMonitor slot, actual successful transport API boundaries, ACK-entry event time separate from M1's processing clock, reliable ACK source separate from the move send source, canonical `video` identity, independent M2 and CRC/T3 FrameKeys, exact reuse of the strict evaluator, and a separate private artifact projection. The actual current product interfaces inspected support these choices. The skipped-move true return, provisional strict-evaluator arrays on failure, raw legacy transcript, and browser-track namespace are addressed explicitly in both drafts.

The plan's serial ownership, focused fake-platform tests, legacy default preservation, privacy caps, no source authority changes, and no operational/native work are useful and proportionate. Missing Host stage values remain independently nullable. The suggested changes above close observable contract gaps within that scope; they do not require a generic collector framework, InputTrace changes, a new capability, or native-target implementation.
