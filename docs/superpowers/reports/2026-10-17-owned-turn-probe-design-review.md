# Owned TURN probe — design review

Read-only review of `scripts/passive_session_soak.py` in reliability-latency worktree (requested HEAD e26b37c). No browser, service, process signal, or repository mutation performed.

## Verdict

Use a private subprocess supervisor plus a thin manager proxy. A proxy alone does not provide an independent wall-clock deadline when launch, cancellation, event-loop shutdown, or driver teardown hangs. CDP is useful corroboration, not the ownership authority. Keep the helper, UI admission guard, and original lifecycle summary unchanged.

## Required corrections

1. **Begin ownership before manager.start.** Launch the private worker with `start_new_session=True`; record its PID and psutil create_time immediately. The supervisor must be a separate process, not an asyncio task on the worker event loop. In this dedicated worker no unrelated subprocesses may be launched. Repeatedly capture descendant PID/create_time and observed parent identity starting before start/launch, through teardown. A successful-launch-only CDP snapshot misses manager.start failure, partial launch, and later renderer children.
2. **Maintain an independent registry.** The launch proxy must store the returned browser before doing any optional awaited CDP work. The helper only assigns its browser after the entire proxy launch returns; CDP failure/cancellation otherwise leaves its browser variable None. Prefer an external ownership monitor and return the browser promptly. Any CDP query must have a short independent deadline and always detach its session; failure is recorded, never replaces the original launch outcome or prompts another launch.
3. **Use CDP only to corroborate.** `browser.new_browser_cdp_session()` plus `SystemInfo.getProcessInfo` may enumerate browser/renderer processes but is not an exhaustive OS process-tree proof. Accept only IDs independently observed as descendants of the dedicated worker, with creation time and parent chain checked while the ancestor identities remain stable. Never adopt a process merely because its executable/name/profile or CDP PID looks right.
4. **PID identity and races.** Cache psutil Process objects with create_time; immediately before each signal re-read identity and use psutil Process.terminate()/kill() rather than raw os.kill. Recheck identity before TERM, before KILL, and before reporting exit. macOS offers no pidfd-style fully atomic identity-bound signal here: a small check-to-signal race remains. Do not claim race-free cleanup. AccessDenied, vanished parent before registration, unknown ownership, or changed birth identity means skip signal and report unknown/reused, never broaden a PID/name search. Avoid killpg: membership can change, and the per-PID owned identity requirement is stricter than group membership.
5. **Launch failure remains partially observable.** A process can spawn and become orphaned between polling snapshots; process-group metadata can aid diagnosis but must not silently turn an unobserved process into kill authority. Report ownership coverage incomplete in that case. Neither CDP nor a polling supervisor proves that zero unobserved descendants exist. Record “all recorded owned identities exited” separately from “complete process-tree exit established”.
6. **Bound finalization independently.** Let the original run finish first, including its 8s cleanup budget; supervisor has a conservative absolute cap covering helper startup, media-start, requested sample interval and cleanup. Do not treat requested duration as total wall time. On return or cap expiry, retain a short observation window, then TERM only still-live recorded owned identities (children first); wait a fixed bounded interval, KILL only matching surviving identities, wait once more. Continue recording descendants of matching live roots during cleanup. The supervisor may terminate its directly created worker after its grace period; preserve original return code and separately mark supervisor intervention. Do not allow late async launch tasks to spawn new children after declaring cleanup complete.

## Smallest workable layout

- One private 0700 evidence directory; wrapper/sidecars 0600, created exclusively. No production or worktree source edits.
- Supervisor launches one worker using the unchanged module’s `run(args, manager_factory=...)`. Worker keeps existing fresh-login, zero-Viewer and one-use proof UI guard. Never retry Start, remint proof, fall back to ordinary admission, or recreate a browser after failure.
- Proxy delegates start/stop and all normal methods exactly; records phase times and optionally browser-CDP identities. Supervisor owns OS registry, deadlines, signals and final process-exit sidecar. Do not write into or reinterpret helper PASS/FAIL or lifecycle evidence.
- Sidecar: worker identity; observed owned identities and parent identities; observation timestamps; CDP corroboration result; launch outcome; helper exit code; deadline/intervention flag; TERM/KILL attempts; per-identity exited/alive/reused/unknown; coverage limitations. Do not dump command lines, environment, URLs, tokens, browser profile contents, or arbitrary errors.

Sampling must run outside the Viewer event loop. Keep sample subprocess ownership separate from the tested browser registry. A same-PID different-birth Host cancels sampling; never discover/restart a replacement Host automatically.

The trigger can watch complete existing samples.jsonl lines without injecting extra browser evaluations; record the lag and that this only observes the helper sampling phase (not its media-start loop). Raw sample output can contain paths and process metadata: keep it private, size-bound, and only derive a sanitized stack summary for versioned reports. Record sample start/end, exit, timeout and overlap with the stall. This run is diagnostic and perturbed, never performance qualification or a replacement long-session acceptance. Host sampling is read-only but adds overhead. No Host/tunnel/service signals are permitted.
