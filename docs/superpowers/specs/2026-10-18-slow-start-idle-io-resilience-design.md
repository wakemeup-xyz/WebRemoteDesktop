## Startup contract

Scope: normal WebRTC initial startup (including automatic retries before its first trusted frame). Existing tunnel/JPEG startup and already-successful session recovery remain unchanged and receive explicit regressions. No codec, bitrate, FPS, quality, network mode, TURN, authentication, admission, lease, reset or proof-policy changes.

An explicit verified Start owns one startup episode before asynchronous admission/bootstrap work. Every continuation checks that episode; a newer explicit Start retires its predecessor before requesting new work. First media init starts its media budget exactly once. Bootstrap retains its existing <=5s dependency deadlines.8s feedback and72s hard media budget are measured from this first init, not falsely called click latency; telemetry keeps original click timestamps. Automatic init/PC/socket/lease replacement inherits the episode's remaining budget. Only a new explicit Start can reset it. A successful episode stops initial supervision and does not constrain established-session recovery.

- At8s without a trusted current frame, remove blocking connecting presentation and show slow-connection text with retry/cancel available. Keep pending/signaling internally, never call terminal failure or suggest a different mode without supporting evidence. Existing media-pending3s/8s hints remain warnings with owned callbacks.
- Keep the DC watchdog's30s negotiation, answer-before-deadline10s channel-open and at most two10s checking extensions. Do not replace them with an early30s global cap. DC open ends only DC supervision. The outer72s media budget caps automatic startup retries and does not promise every later retry its full independent DC allowance.
- The first trustworthy connected state of each current PC starts a12s paint budget, capped by the outer episode remainder. Duplicate connected/answer/track/metadata/stats/lease events do not reset that PC's paint budget. An explicitly replaced owner may use a new paint phase only within the unchanged outer remainder. DC open never cancels pending paint supervision.
- Budgets count visible, intentionally active waiting. Hidden/intentional-pause transitions stop new first-frame error reporting and pause only the new supervisor's remaining budgets; resume uses the exact remainder, never a fresh budget. Existing pause/resume/DC policies are not rewritten. Repeated pause/resume cannot buy more active waiting. Report this as active waiting, not a wall-clock completion guarantee.
- Timers only wake checks. Use monotonic elapsed accounting; early callbacks wait the remainder, late callbacks settle expiration before accepting new progress. Invalid/backwards time cannot purchase budget; keep a finite fallback. Hard expiration is terminal exactly once with phase-appropriate fixed reason and retry UI, without an automatic network/quality change.

Each episode/owner records identity only in memory: episode token/sequence, current attempt, PC, socket/signaling generation and offer epoch where applicable. Older queued callbacks cannot mutate new timers/UI/readiness/input. Before hard terminal cleanup, retire the episode/owner, then cancel owned timers/reconnect/signaling-recovery and pending bootstrap/offer continuations; close/detach its producer through existing teardown primitives and freeze input through existing safety/reset paths. Do not use logout or manual-disconnect as a general timeout shortcut. Hard-terminal old work cannot revive via socket connect, Host-online, answer, DC open or frame. Host-offline retires its old media owner; any authorized automatic retry before the episode expires must use a new owner and the same remaining budget. Manual disconnect, superseded/kick and auth-invalid retain their existing terminal authority.

Success requires existing trusted current-frame readiness, never DC open/ACTIVE lease/ACK alone. Existing full Input conjunction remains authoritative. A frame before grant may complete media startup while input stays closed. Do not relax the existing disconnected terminal gate; late valid completion is permitted only while the new supervisor is pending/slow. The first RED must use actual Viewer plus actual Input gate, not just a reducer UI assertion, and demonstrate >8s answer/frame while the intended active lease/socket remain valid.

## Bounded Host file writer

Preserve configure_host_logging, emit_host_event, ordinary logger calls, existing structured redaction/schema/return values, log path/format,10MiB+3 defaults and environment bounds. Root handler becomes a facade; normal producer emission formats/freezes once and admits immutable text with put_nowait, with no file I/O, capacity wait, writer flush or stderr fallback. Existing formatting/redaction still costs CPU; do not promise lock-free/real-time behavior or universal sanitization of old free-text callers.

Freeze constants:64 queued entries plus at most1 in-flight; each admitted formatted UTF-8 line <=65536 bytes. Drop an oversize line as a whole, never truncate structured JSON. At most~4.063MiB queued/in-flight text (Python overhead is additional); no LogRecord/args/extra/exception-frame graphs retained. Fixed counters for accepted/processed/full/oversize/closed/writer-error/abandoned saturate at2^53-1 with a saturation flag. No rejected contents or per-user dictionaries. A cached fixed snapshot may expose queue depth/capacity/counters/writer/stop status; no queue contents. Sink error handling suppresses default raw record/traceback stderr fallback.

Exactly one owned daemon writer performs rotation/open/write/flush/close. It holds no producer/queue/state lock while doing file I/O. No replacement writer while the prior writer is alive. Same-signature configure is idempotent for a live facade; stopped-but-alive reconfiguration is refused with a fixed error. Startup/control-plane path resolution remains distinct from steady-state logging.

The facade must not serialize producers behind logging.Handler's implicit I/O lock while another thread waits in flush/close. Use no facade I/O lock (with explicit short queue/counter synchronization) or an equivalent handle implementation; flush/shutdown waits hold no producer lock. This applies to automatic logging.shutdown as well as explicit control-plane calls.

`flush(timeout=...)` uses an admitted-prefix watermark and out-of-band coalesced request; default budget1s, returns success/failure. While requests remain outstanding, the owner flushes/publishes each advanced completed prefix before dequeuing later writes; newer requests cannot postpone older or intermediate completed callers. Metadata remains bounded scalars, including explicit empty-prefix flush. It never flushes the file on the caller. `shutdown/close` stops admission, uses an out-of-band stop Event and <=50ms queue polling, and shares one default1s total deadline across drain/flush/join. Full queue does not require sentinel admission. Expiry abandons queued work with counters; a blocked in-flight writer may remain alive, explicitly reported, never concurrently closed/replaced. Repeated close is harmless. Ordinary logging never calls flush. Existing rotation tests use bounded flush without sleeps and close their owned handlers.

Cover stdlib logging.shutdown's implicit acquire/flush/close of every constructed handler. The internal rotating sink must be writer-only (no cross-thread I/O lock and non-owner flush/close no-op, or equivalent public-API solution); the facade's automatic flush/close must remain finite. Do not modify private logging handler registries. Automatic flush and close are each bounded; do not claim one global shutdown bound for arbitrary unrelated handlers. Integrate an explicit owned stop after final Host lifecycle messages; no default-executor join that can make asyncio.run wait forever.
