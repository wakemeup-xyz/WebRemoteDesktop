Critical heartbeat interpretation: engine packet with type ping means observed incoming ping, not a heartbeat RTT sample. packetCreate with type pong means queued outgoing pong; it occurs before writeBuffer.push/flush. The engine pong event is emitted immediately in the incoming ping branch, after enqueueing pong, not on receipt of a remote pong. engine flush means transport.send was invoked for a batch, not that a particular pong was delivered or acknowledged. These are conceptual event descriptions; persist only the compact k enum defined below (rx/tx/ef/ep/eo), never duplicate long event names or direction fields. Never label packetCreate, pong, or flush as wire-send confirmation or successful heartbeat exchange. Upgrade probe ping/pong travels through an alternate candidate transport and bypasses the current engine packet pipeline; missing such events is not evidence that a probe never occurred. Do not inspect packet.data to distinguish probe payloads.

connect_error may be either a local transport error or an Error created from arbitrary server packet data. Therefore do not persist or forward error.message, error.data, error.context, stack, description or arbitrary error.code. A useful fixed mapping is type exactly TransportError => transport-error; everything else => unknown. If a future task proposes another category, prove its installed API and add an explicit exact-value whitelist plus leakage tests. UNKNOWN is acceptable and must remain when no typed signal exists.

Socket close reason whitelist: io server disconnect, io client disconnect, ping timeout, transport close, transport error, parse error, forced close; other/missing/nonstring => unknown. Engine/Manager close uses the compatible subset; any new string stays unknown. Emit the event kind and fixed reason separately; never copy raw strings into another field.

## Binding and coverage

At observer construction, sample(), diagnostic snapshot and the single 1s scheduler callback, resolve the current WebRTC.socket, socket.io, and manager.engine. Bind available objects idempotently and detach all own listeners from replaced objects. Listen to Manager open and Socket connect to re-evaluate the current engine promptly; Manager reconnect_attempt can schedule a microtask that only rechecks existing references after the synchronous engine assignment. No polling faster than the existing 1s schedule and no new socket are necessary. A proposed 100ms attachment poll would still have a blind window and would require an explicit additional overhead review; it must not be sold as complete interception. This narrow design uses the single 1s timer plus existing event hooks.

Every callback must guard stopped=false and be tied to an object this observer actually enrolled. Product disconnect/close listeners often run first and can clear the lease or replace client.socket/manager.engine before the observer callback runs. Therefore exact current-reference equality MUST NOT discard an already-enrolled close/disconnect cause. Assign bounded run-local labels (socket-1/manager-1/engine-1, WeakMap/capped counters, maximum 64 binding changes) without reading Socket.id or engine.id, and persist the local label plus isCurrentAtCallback boolean. Never persist a real Socket/Engine/attempt ID. An enrolled old object event remains in this run ring with false currentness; it is not current authority and cannot independently be assigned as the current run initiating cause. Limit attached objects to one socket, one Manager and one engine. Replaced objects lose all own registered listeners/timers promptly. An emitter may have copied listeners before detachment, so an in-flight callback can still record a bounded old-object terminal event, marked false; do not trade away the first close reason to hide that edge. At capacity, record fixed observer-capacity and mark coverage incomplete; do not recycle labels or claim continuity.

Install after successful UI login and before Start if the Viewer has initialized its application objects; keep the exact existing one-use Start protocol. This catches more of establishment without modifying product code. Missing references are normal and recorded as unavailable. The harness cannot intercept every newly created engine between scans, especially pre-open errors before the Manager listener is bound. Record observedFromMs, boundAtMs and coverage gaps/replacement counters; never infer a missing disconnect/ping/connect_error from absence of events. First sample may already be disconnected; preserve state-observed-disconnected with firstDisconnectEvent=null.

Because product listeners can run first, an observer callback may see already-mutated application state. Record only the exact supplied fixed reason and current reference/state facts, not an invented sequence across components. In particular, socket!==client.socket does not erase the observed enrolled Socket close; preserve its local label and false currentness. Keep actual event record order with a monotonically increasing observer sequence number.

## Bounded browser record

Nested diagnostics schemaVersion=1 is independent of existing sample schemaVersion=1. Capture anchors once: browserWallEpochMs=Date.now(), browserTimeOriginEpochMs=performance.timeOrigin if finite, browserAnchorNowMs=performance.now(). Epoch anchors are finite nonnegative integers <=9999999999999 or null. They associate log windows only; never calculate cross-clock latency from them. Event time is a rounded monotonic integer relative to observer construction. The following compact schema is REQUIRED, not a suggestion to include every field on every event.

All events have exactly t (0..43320000 elapsed ms), n (1..999999999 ordered sequence), k (fixed enum). Optional keys are permitted ONLY by the table. Counters saturate at 999999999 with coverage status capacity; at elapsed/sequence limit emit the reserved fixed capacity marker if possible and mark coverage incomplete. Do not wrap or synthesize an event time. Object label o is a run-local s1..s64/m1..m64/e1..e64, never a real object ID; c is the exact boolean isCurrentAtCallback. No free strings, decimals, implicit null optional keys or other keys are permitted. All terminal events require o/c/r even if c=false. Cleanup phase is inferred from the ordered preclose event plus Python close boundaries; direction is implied by k, so neither is duplicated per event. Transport name appears only in bounded binding/current-state metadata.

| Event kinds k | Required additional keys | Optional keys | Compact ASCII JSON maximum at numeric bounds |
| --- | --- | --- | --- |
| sd Socket disconnect, mc Manager close, ec Engine close | o,c,r | none | 79 bytes (worst reason transport-error, c=false) |
| se Socket connect_error, re Manager reconnect_error | o,c,r with r transport-error/unknown only | none | 79 bytes |
| rx heartbeat packet received, tx heartbeat packet created | o,c,p with p ping/pong/unknown | none | 71 bytes |
| sc Socket connect, mo Manager open, ra reconnect_attempt, rr reconnect, rf reconnect_failed, ep Engine ping, eo Engine pong, ef Engine flush, eu Engine upgrade | o,c | none | <=59 bytes (longest k rf is shorter than bind below) |
| bind object enrolled | o,c | none | 59 bytes |
| vis visibility state | v visible/hidden/prerender/unknown | none | 54 bytes |
| net online state, focus focus state | v boolean/null | none | 50 bytes (k focus, v=false) |
| hide/show/freeze/resume browser lifecycle; preclose cleanup marker; cap capacity marker | none | none | <=43 bytes (longest k preclose) |

r mapping: io server disconnect=>server; io client disconnect=>client; ping timeout=>ping; transport close=>transport-close; transport error=>transport-error; parse error=>parse; forced close=>forced; every other/missing value=>unknown. Keep this mapping and per-object compatible reason subsets explicit in JS and Python. State-observed-disconnected without a delivered terminal event is snapshot state only, never a synthesized sd/ec. firstDisconnectEvent is either null or one exact terminal record above, plus separately fixed cause=unknown until attribution exists. An old-object close can be the first observed event with c=false; that is not enough to assign it as the current connection cause.

These byte counts were computed using compact ASCII JSON (no spaces); implementation tests must enumerate all schema variants at numeric, reason, label and boolean bounds and compare actual UTF-8 lengths. Every event remains capped at 192 bytes, leaving explicit spare capacity without increasing any budget. Terminal overflow MUST NOT be silently discarded: set coverage incomplete and a fixed schema-capacity failure; preserve the separately validated first terminal record or null if it cannot safely be represented. Ring capacity128, overwrite oldest with saturating droppedEvents. Unknown and unavailable are distinct from zero observed events.

Explicit lifecycle.json allocation: event-array value <=24705 bytes (128*192+129 punctuation); every byte outside that value <=8063. Sub-budgets inside the 8063 are anchors512; first terminal record and attribution384; fixed event counters1024; browser state/lag1024; binding/coverage metadata1024; Python lifecycle/cleanup2048; headers/capture/write status512; remaining1535 reserved for envelope keys/punctuation and safe future fixed fields. Total allocated8063. Enforce each sub-budget and final compact file <=32768 bytes before atomic replacement; never emit indentation for this file. Bounded overflow fallback consists only of validated anchors, first terminal record if available, fixed statuses and cleanup; it omits tail-ring entries and marks coverage incomplete, never silently truncates a terminal field or arbitrary JSON bytes.

Keep only fixed event counters and last observed pingReceivedAtMs/pongCreatedAtMs/flushAtMs within those sub-budgets. Drain at most16 events per sample: event-array <=3089 bytes (16*192+17); all other delta keys/metadata <=1007 bytes; complete diagnostic delta <=4096 bytes. Retain full ring for final snapshot. Validate cursor/gap/truncated metadata and byte caps independently; do not copy full history into every sample. Existing sample MAX_ROW_BYTES32768 stays unchanged.

Browser lifecycle: read initial visibilityState => visible/hidden/prerender/unknown, navigator.onLine => true/false/null, document.hasFocus() => true/false/null. Observe only visibilitychange, online, offline, focus, blur, pagehide/pageshow and supported freeze/resume. Do not store URLs or page titles, beforeunload content, DOM events or focus target. Visibility/online/focus are observations, not network-delivery or physical-display proof.

Use one cancellable 1000ms monotonic scheduler: lagMs=max(0, now-expected), missedIntervals derived arithmetically, then advance to the next expected future deadline. Do not loop once per missed interval or enqueue catch-up work. Keep bounded last/max/count and fixed lag buckets; retain a capped recent window if p95 is desired. A browser 1s timer lag is main-thread scheduler evidence, not proof that Signal or Host stalled. Existing Python late/missing samples remain independent, unchanged evidence. The interval callback only binds existing references and records summaries; no fetch/getStats/input from it. getStats remains only the existing sampler call with its existing 800ms deadline.

stop() idempotently cancels this one timer, removes exact own socket/Manager/engine/DOM listeners, cancels existing rVFC and relay load listeners, and prevents late callbacks from writing. Returning a final immutable sanitized snapshot must remain possible after stop. Never call socket/engine/manager close or change reconnection.

## Python failure and cleanup order

Use an OUTERMOST evidence-finalization try/finally that owns output state before Playwright manager entry and remains active until after manager teardown. A helper only inside the current inner browser try/finally is insufficient. Prefer explicitly managed async_playwright().start()/Playwright.stop() with an injectable manager factory; equivalently a bounded manager wrapper is acceptable. Do not rely on an unbounded async-with __aexit__ after browser.close. Initialize browser/page/manager handles to absent, first-failure and original-cancellation state, safe empty evidence and output budgets before entering that outer scope. Commit initial lifecycle.json AND summary.json with fixed INCOMPLETE/not-started state before manager start, so launch/entry failure still has evidence.

Every awaited lifecycle stage has a finite deadline: manager start <=10s, browser launch <=15s; existing authorized navigation/Start/media deadlines remain unchanged. One cleanup coordinator has a total <=8s monotonic budget INCLUDING cancellation settlement: final browser export<=1s, browser.close<=3s, manager.stop/exit<=3s, leaving <=1s for cancellation draining/finalization accounting. Each stage uses the minimum of its cap and remaining budget; do not chain fresh full budgets after expiration. Synchronous bounded JSON validation/atomic file writes still occur in the outer finally, even if the async teardown budget is exhausted. Filesystem errors retain the last committed preliminary files and a fixed local write status when possible; no software guarantee is made for process kill/power loss or a blocked OS write.

Handle asyncio.CancelledError separately from Exception on current Python. Capture the original cancellation once, perform protected bounded cleanup covering manager teardown AND evidence finalization, then re-raise the original cancellation. Cleanup exceptions/timeouts never overwrite the first sampling/start/launch failure or cancellation. A later teardown failure is a separate fixed status and cannot turn an INCOMPLETE proof into PASS. Cancellation during manager start, launch, manager exit and cleanup must all enter the same outer finalization path. Repeated cancellation cannot continually restart the budget or prevent the synchronous final file attempt.

No detached or indefinitely pending cleanup task is allowed. The coordinator must own all stage tasks, cancel timed-out tasks, and await their cancellation settlement within the remaining cleanup budget; tests assert no live task survives return. Using asyncio.wait_for alone is insufficient because cancellation-resistant awaitables may prevent its return. A stage which fails to settle under cancellation is an implementation blocker for this narrow in-process design, not permission to report success or detach it. Do not claim hard teardown guarantees for an API whose cancellation behavior is unverified. If real Playwright cancellation proves non-cooperative, stop the narrow implementation and seek scoped review of an owned subprocess boundary; introducing a worker/process supervisor is not implicitly authorized by this brief. No live browser is required to approve the design or its offline fake-manager behavior.

Required order and timestamps:

1. On any first failure (including manager-entry/launch failure), save the fixed stage/reason and Python monotonic failureDetected time plus association wall anchor. Preserve the earliest observed browser terminal event or null; continuity remains INCOMPLETE after the original first disconnect.
2. If a page/observer exists, make ONE ordered bounded browser evaluate: append preclose marker, take sanitized final snapshot, stop own observation/listeners, return the final snapshot. Snapshot-after-stop must not bind objects, add listeners or start timers. If unavailable/timeout/error, preserve the last validated diagnostic delta with a fixed capture status and unknown first event where absent. Do not serialize an exception. An absent browser/page/observer is valid initial failure evidence.
3. BEFORE browser.close, commit BOTH preliminary lifecycle.json AND preliminary summary.json containing original failure and current export/cleanup status. Safe initial files from before manager start remain if these replacements fail. Record Python browserCloseStarted; close only the owned browser if one exists, with its bounded stage budget; record browserCloseFinished and closed/timeout/error/not-created. No browser evaluate is attempted after close.
4. Record separate managerStart/managerLaunch/managerStop started/finished Python monotonic fields and fixed status ok/timeout/error/cancelled/not-started. Bound manager.stop or equivalent __aexit__, even after browser.close timeout/error. No browser may have been returned when launch failed: manager teardown still executes if manager exists, and the outer finally still runs if manager start itself failed.
5. Outermost finally writes BOTH final artifacts after manager teardown outcome, each via validated compact serialization and safe same-directory atomic replacement. Include fixed per-stage capture/close/manager/write statuses without arbitrary errors. Preserve preliminary artifacts if final replacement fails. Then propagate the original cancellation, otherwise report original failure/INCOMPLETE status.

Owned-process claims require separate evidence. A returned browser.is_connected=false or successful close/manager.stop is an API outcome, not process-exit proof. Record ownedProcessExitEvidence as not-observed by default; no-owned-processes-left may be asserted only with actual ownership-linked exit confirmation for the created browser/driver, never by a global process-name search or absence of a handle. Fake tests prove cleanup ordering and no pending fake task; they do not prove real process exit. Do not kill shared browsers, unrelated PIDs, services or tunnels. Failed launch/teardown without ownership-linked process evidence remains cleanup incomplete/exit unknown even when artifacts are correctly saved. This task need not promise process absence to deliver useful bounded failure evidence.

Do not classify the harness-close period as a production disconnect cause. The pre-close browser marker and Python closeStarted are distinct: anchors provide association, while actual ordering inside one clock domain provides the reliable sequence. Engine close emitted as a consequence of browser shutdown may never reach an observer snapshot; missing that event is expected and must not be invented.

Output: existing output directory mode0700; samples.jsonl/summary.json/lifecycle.json mode0600, no credential-bearing filenames, exclusive creation and safe same-directory replacement. lifecycle.json <=32768 bytes including anchors, ring, compact first-disconnect and Python cleanup. Keep existing per-sample32768 byte and total64MiB budgets unchanged; count lifecycle+summary in the total run budget and reserve TWO MAX_ROW_BYTES files before samples consume it: samples <=67108864 - 2*32768 =67043328 bytes; summary<=32768 and lifecycle<=32768. Replacements do not add logical artifact bytes, but the temporary atomic-write disk footprint is separately bounded. Never let exhaustion suppress the original failure report. Existing summary can refer to the fixed filename and compact status only. Validate allowlisted keys/types/enums and size in Python before disk; do not persist arbitrary browser-returned dictionaries as an unchecked fallback.
